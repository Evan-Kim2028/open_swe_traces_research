**3. 12 of 30 units fail 0/n at L0 — a real 40% difficulty rate.** The standing finding "every unit that passes L2 also

## Sampling policy change (2026-09-19, from this sweep's determinism)

**k=1 at the screening level (L0), k=3 only on escalation (L0→L2).** Justification: 27/30 units gave an identical
outcome on every attempt (90%); only gin/formmapping (1/3), kops/flagbuilder (1/2) and helm/coalesce (2/3) are mixed.
A single trial therefore classifies a unit correctly ~90% of the time, and the ~10% it misclassifies are exactly the
mid-difficulty units, which a follow-up attempt resolves cheaply. Rule C6 ("one pass suffices, two runs at the flip")
came from Terminal-Bench, where per-task rates sit near 50% and single trials genuinely are unstable; on this bank they
are not. The measurement that must stay precise is the flip itself, so escalation keeps k=3.

Consequence: the same ~$26 that bought 30 units × 3 attempts buys ~90 units × 1. Screening cost per unit drops from
~$0.87 to ~$0.29. This is the lever for going from ~30 units to 100+.

## The four L2 non-flippers are PACKAGING DEFECTS, not capability limits (solver-free, `climb_l3_l6.md`)

Re-reading each failing property against the contract row it maps to, with gold as ground truth, resolved all four
**without a single trial**. In three cases the contract *contradicts* gold; in the fourth the assertion has no row.

| unit | what the contract says | what gold does |
|---|---|---|
| helm/depresolver | "a sha256 over the canonicalized (sorted) requirement set" | `json.Marshal([2][]*chart.Dependency{...})` — a different encoding, and the test asserts an exact literal digest |
| helm/ignorerules | "there is no negation: `!` is a literal character"; implies `**` is supported | `!` sets `p.negate` and a non-match under a negated rule returns true; `**` is a parse **error** |
| helm/repindex | "a filename that is already an absolute URL is used as-is"; "an existing entry is replaced, not duplicated" | always `filepath.Split` → basename → `URLJoin(base, file)`; and unconditional `append`, so duplicates accumulate |
| kops/clustervalid | (nothing) | constructor must error on an empty InstanceGroup list — **no coverage row and no prose states it** |

**A model that followed the L2 contract faithfully was guaranteed to fail.** These units were never hard; they were
mis-specified. This is the failure mode the author/verifier role separation creates: the verifier author wrote
properties from the excised code's real behaviour while the task author wrote prose from their reading of it, and
nothing checked the two against each other.

**New rule for `verifier_rules.md` (A-series, validity):** *the contract must be consistent with gold.* Every coverage
row's prose must be true of the gold implementation, and every hidden assertion must map to a row. This is checkable at
packaging time with no solver, and it would have caught all four. Add it to the gate alongside A1/A3/A8.

**Consequence for the flip certificate.** The "fail L0 + fail L2 → investigate" branch is not a rare tail; it caught a
systematic authoring defect on 4 of 12 units (33%). Investigation must happen before a unit is labelled hard.

### Pre-registered prediction now under test
The missing information lives only in the hidden test file, so neither L3 (test names) nor L4 (signatures) can repair
it; the first rung that can is L5. All four are predicted to flip at **L5**. L3 is running now (k=3, 12 trials); if a
unit flips at L3 that means name/signature cues were enough, which would be a different and weaker story.

**L5 ≡ L6 on this bank**: each of the four units has exactly one hidden test file, so "restore one" and "restore all"
produce byte-identical trees. A flip at L5 is the strongest signal this ladder can emit here — we cannot distinguish
"needed one assertion" from "needed the full spec".

## ADVERSARIAL CONTRACT — VERDICT: the contract is load-bearing and outranks the code

24 trials, k=3, $7.21. Each unit is its preflight-PASS L2 dir with exactly ONE coverage row inverted against gold;
tree and hidden suite byte-identical (checksums in `adversarial_contract.md`). The hidden suite still asserts gold, so a
model that believes the lie must fail that property.

| unit | L2 (truthful) | L2-lie | failing test under the lie | is it the lied-about row? |
|---|---|---|---|---|
| gin/jsonrenders | pass | **0/3** | `TestJsonpJSONCallbackProperty` (+`TestJSONMarshalErrorProperty`) | **yes** (jsonp wrap) |
| gin/streamrenders | pass | **0/3** | `TestDataContentLengthProperty` | **yes** (empty-body Content-Length) |
| kops/addonparse | pass | **1/3** | `TestAddonParseEmptyInvalidProperty` | **yes** (empty input) |
| kops/issuecert | pass | **0/3** | `TestIssuecertClientServerProperty` | **yes** (SAN trim) |
| kops/memfs | pass | **0/3** | `TestMemFsCreateWriteProperty` | **yes** (exclusive create) |
| kops/oidcdisc | pass | **0/3** | `TestOIDCDiscoveryDocumentProperty` | **yes** (404 when no OIDC) |
| kops/templater | pass | **0/3** | `TestTemplaterSnippetNameProperty` | **yes** (reserved-name collision) |
| kops/assetsremap | pass | **3/3** | — | n/a — **survived the lie** |

**7 of 8 flipped from passing to failing, and every one failed on exactly the property that was lied about.** The
pre-registered prediction ("7 of 8 fail on the lied row; assetsremap still passes") was exact.

### What this settles
1. **The instruction IS the information channel.** With correct code in front of it, the model implements the prose.
   Inverting one sentence reliably inverts the behaviour. The ladder measures what it claims to measure.
2. **The one survivor localises the mechanism.** `kops/assetsremap`'s lie was comma → `%2C` in file remap — a fact the
   callers already pin. It ignored the contract there and read the tree. So the contract is load-bearing **precisely
   for facts the surrounding code does not determine** — which is exactly the definition of unit difficulty this bank
   converged on independently (`authoring_hard_l0_units.md` §2). Two independent routes, same boundary.
3. **The 40% bank-wide contract-defect rate is therefore a real silent error rate, not a curiosity.** 11 units have a
   FALSE coverage row; on this evidence a false row reliably produces a wrong implementation. Those 11 units'
   measurements are not what we recorded them to be, and the 9 missing-row units are under-specified in the same way
   `kops/clustervalid` was.

### Consequences (actioned)
- Every result from a defective unit is **provisional** until re-authored. The bank's usable size is 30, not 50.
- Contract-vs-gold consistency becomes an A-series validity rule at packaging time — solver-free, and it would have
  caught all four climb units and all 20 of these.
- Re-author the 11 false-row units; re-screen them; only then do their L0/L2 numbers count.

### The result: 1 confirmed hack in 245 passing attempts

This is the one attack the defences could not stop, and the reason is structural: **the container egress allowlist

the image can reach them. Detection, and voiding the trial, is the only available control.

clean evidence it is **0/3 at L3** — and it was never carried to L4/L5 *because* it appeared to have solved. Re-run

## THE FIRST UNSOLVABLE UNIT — and it is our fault too (new rule B10)

`sweep_dblL5` is **19 of 19 passing**: every remaining double-failure family solves at L5, first attempt. With

Except one. **`helm-depresolver` fails at L5.** It is the first unit ever to fail with the hidden test sitting in

```go
expectHash := "sha256:fb239e836325c5fa14b29d1540a13b7d3ba13151b67fe719f820e0ef6d66aaaf"
h, err := resolver.HashReq(req, lock)
```

The solver produced `sha256:208c6282…` — **the same digest in both tests**, so it did build a stable, correct

> "the lock hash is a sha256 over the canonicalized (sorted) requirement set, so two equivalent requirement lists

expected digest tells you nothing about how to produce it.

### Rule B10 — no literal digests of internal serialisations

> A hidden test must not assert a hard-coded digest of a value the solver serialises. It pins the byte layout, not
> the behaviour, so it is unsolvable from any contract and unsolvable at L5. Assert the *property* — equal inputs
> hash equally, different inputs differ, the digest is stable across runs — or compare against a digest the test
> computes itself from a value it also constructs.

`scripts/ops/literal_digest_audit.py` sweeps the bank for this. **Exactly two families carry an algorithm-prefixed
digest literal**: `helm-depresolver` (the oracle above) and `kops-assetsremap`, whose
`sha256:0123456789abcdef…` is a synthetic *input* fixture, not an expected output — and which passes 2/3.

So the bank contains exactly one unsolvable unit, it was unsolvable by construction, and the defect is a verifier
rule we had not written yet. **Still zero capability limits.**

### Two defects in the generated text, both worth fixing

1. **The B7 symbol scrubber substitutes the literal string "the call"**, so sentences read "the call combines two
   indexes" and "the call walks a directory for *.tgz files". Ambiguous wherever more than one operation is in
   scope. It should substitute a descriptive noun phrase ("merging", "the directory scan"), not a fixed token.
2. **"prereleases sort before releases of same core version"** — in *descending* order `1.0.0` comes before
   `1.0.0-beta`, so this row is backwards. It is precisely the class of error that regressed my round 4 from 1/3
   to 0/3. A related worked example looks wrong too: `Get(">=1.0.0")` returning `2.0.0-alpha` as the highest match,
   when that constraint form does not match pre-releases.

### Head-to-head running now

`sweep_rc_auto` puts the generated contract on the same unit at L2, against the hand-derived 29-row contract's
**2/3**. The generated contract's coverage table is 8 rows (one per hidden `Test*` function) rather than one per
assertion — but its *prose* carries the per-assertion detail, so the granularity may arrive by a different route.

**This is the structural point the rcfix ladder was built to test.** The reconciler's granularity is inherited from
the hidden suite's: where the verifier writes one `TestDetailNN` per commitment (the per-detail grading
convention), one row per test *is* one row per assertion. `helm-repindex` predates that convention and bundles 50
assertions into 7 test functions — the hardest possible case for the method, which is why it is the right test.

### Head-to-head: the generated contract is 0/3, and it fails on exactly the two defects predicted by inspection

`sweep_rc_auto` — the reconciler's contract, unedited, at L2 — **0/3**, against the hand-derived 29-row contract's
2/3. The failures map one-to-one onto the two defects flagged when the text was first read, plus two omissions:

| failure | attempts | cause |
|---|---:|---|
| `beta not sorted desc: [3.3.9 3.2.8-beta.2 3.2.8+build1 …]` | 2 | **predicted defect 2** — "prereleases sort before releases of same core version" is backwards for descending order. The solver put `3.2.8-beta.2` above `3.2.8+build1`, doing exactly what the row said. |
| `Get("1.0.0 - 3.0.0") expected error, got 1.5.7-alpha` | 1 | **predicted defect 2 again** — the generated worked example `Get(">=1.0.0") → 2.0.0-alpha` taught the solver that range forms match pre-releases. They do not. |
| `Get("1.2") … want 1.2.4` | 2 | omission: partial versions as ranges |
| missing apiVersion · `sha256:`-prefixed digest | 1 each | omissions (my rounds 1, 2 found these) |

**Predicting the failures from the contract text, before running, and then having every prediction confirmed, is
the strongest evidence yet for the whole thesis.** The contract is not one input among several — it is the thing
being executed. A wrong sentence does not confuse the solver; it is faithfully implemented.

It also sharpens the ranking of defect types. The generator's recall is excellent — it found in one pass nearly
every commitment that cost me five rounds — but **recall is not the binding property; precision is.** Two wrong
sentences out of a dozen were enough to take it from (probably) passing to 0/3, while my hand version with fewer
correct commitments but no wrong ones scored 2/3.

`sweep_rc_auto2` patches exactly those two rows plus the two omissions. If it flips, the generator needs two fixes
rather than a redesign:

1. never state pre-release ordering as a *direction* — state it as the pairwise rule against the release it belongs
   to, and say build metadata is ignored;
2. derive worked examples from literals the test actually uses, never from an invented example — the invented
   `>=1.0.0 → 2.0.0-alpha` is wrong about the library's own semantics and no assertion in the suite supports it.

Add: the B7 scrubber must stop substituting the bare token "the call".

### The two predicted fixes move it: generated contract 0/3 → 1/3

`sweep_rc_auto2` — the generated contract with exactly the two predicted defects corrected (pre-release ordering
stated as a pairwise rule, the invented `>=1.0.0 → 2.0.0-alpha` example replaced with one the suite supports) plus
the two omissions added — scores **1/3**, up from 0/3, against the hand-derived contract's 2/3.

That closes the loop causally. The failures were predicted from the text, the predictions were confirmed by the
run, and correcting exactly those sentences changed the outcome. The generator needs two narrow fixes, not a
redesign:

1. never state pre-release ordering as a direction; state the pairwise rule against the release it belongs to and
   say build metadata is ignored;
2. derive worked examples only from literals the hidden suite actually uses — an invented example can be wrong
   about the library's own semantics, and this one was;
3. (cosmetic but real) stop substituting the bare token "the call" for scrubbed symbols.

## DEVIN AS SOLVER: the flip certificate is NOT fully model-independent

`scripts/ops/devin_solve.sh` runs the Devin CLI host-side on a copy of `environment/src`, bakes the result into the
unit's own image and scores it with the unit's own `tests/test.sh`. First results on units Composer fails at L0:

| unit | Composer L0 | Devin swe-2-max L0 | time |
|---|---|---|---|
| gin-clientip | 0/1 | 0 | 216s |
| go-github-netconfig | 0/1 | **1** | 195s |
| go-github-projectsjson | 0/1 | 0 | 354s |
| helm-copyst | 0/1 | 0 | 345s |
| helm-tlsutil | 0/1 | **1** | 302s |

**Devin solves 2 of 5 certified-hard units at L0.** "Certified-hard" is therefore partly a property of the solver,
not only of the task. The flip certificate still proves *fair and solvable* — a unit that flips is verifiable and
has a reachable solution — but "hard at L0" is a claim about **the model that screened it**, and it does not
transfer wholesale to another model.

Consequences:
- L0-hard rates are only comparable within a solver. The cohort table above is a Composer table.
- A bank meant to measure a frontier boundary needs its L0 screen run by more than one model, and the interesting
  set is the **intersection** (hard for every screened model), which is smaller than any single model's set.
- It also suggests a cheap, real difficulty lever that survives where closure size and assertion count died:
  **cross-model agreement.** A unit both models fail at L0 is hard for a reason neither model's idiosyncrasies
  explain. That is worth testing on the full 51.

## RETROSPECTIVE: would call-graph evidence have helped? Yes — and on a different defect class

The static linter's prose heuristics scored at the base rate (40% vs 39%) and were demoted. A crude *structural*
proxy, computable from artifacts already on disk, does considerably better. For each L2 unit:

    GOLD    = functions gold.patch modifies
    ORPHAN  = gold-touched EXPORTED functions the hidden suite never names
              (behaviour the solver must implement that nothing verifies)

Measured on the same 127 units with known outcomes (50 non-flippers, base rate 39%):

| gate | blocked | precision | non-flippers caught |
|---|---:|---:|---|
| ≥1 orphan | 38 | **50%** | 19 of 50 |
| ≥2 orphans | 30 | **53%** | 16 of 50 |
| ≥4 orphans | 3 | **100%** | 3 of 50 |

Mean orphan count: **0.48 for flippers, 1.28 for non-flippers — 2.7× separation.** That is real signal where row
counting had none, and this is only regex name-matching. Genuine transitive reachability should do better, which
is what the `CGCOV` job is now measuring.

### The important qualification

This metric does **not** detect the contract defects. It compares *gold against the suite*, so it is blind to
whether the prose describes either of them. `helm-repindex`'s five contract revisions — which moved trial outcomes
0/3 → 0/3 → 1/3 → 0/3 → 2/3 with gold and the suite held fixed — all have an identical orphan count.

So there are two distinct defect families and they need two distinct instruments:

| defect | example | detected by |
|---|---|---|
| **packaging**: the suite does not cover the excision | gold changes 4 exported functions, the suite exercises 2 | orphan count / codegraph — **works today, 53% at ≥2** |
| **contract**: the prose contradicts or omits an assertion | "replaced, not duplicated" vs a test asserting it appends | shadow implementation; not any static check |

Codegraph is a genuine complement, not a substitute — and it is cheap enough to run on every unit at packaging
time, before a single trial.
