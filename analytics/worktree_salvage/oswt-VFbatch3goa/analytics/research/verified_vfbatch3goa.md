## `Inferable: no` assertion policy

For `no` lines the suite asserts shape only: an error is produced and the diagnostic
names the offending field/type/name (distinctive `bb*` identifiers), or the stated
structural outcome holds (pointer identity, set membership, suffix/prefix patterns,
parameter presence). Exact error prose is never asserted. For `partially`, only the
stated derivable part is pinned.

## Per-unit notes

### secschemes — `expr/security.go` (12 details)
Self-contained; direct construction of `SchemeExpr`/`FlowExpr`, no DSL needed.
`no` lines asserted as shape: invalid-scheme error names the scheme; flow validation
errors name the offending field; canonical scheme kinds checked by set membership.

### svcexpr — `expr/service.go` (12 details)
Mixed direct construction + `expr.RunDSL` (server finalize). Gotcha discovered:
`Validate()` returns a non-nil `*eval.ValidationErrors` with `len(Errors)==0` on
success — all "no error" assertions check the error slice, never `NoError`.
`no` lines: error-presence + field-name assertions only.

### defval — `expr/attribute.go` default validation (12 details)
Same `len(verr.Errors)==0` pattern. Probes showed: enum-default compatibility needs
same-kind types (Int32+int32, not Int+int64); `Format` on a non-string attribute is
a DSL-definition error; non-string map keys report the key type; struct defaults
match per design field (extra struct fields ignored; missing required / wrong-typed
matched fields error). `no` lines: error presence + offending field/key-type names.

### rootval — `expr/root.go` (14 details)
Walk-order classifier accepts both `*expr.UserTypeExpr` and `*expr.AttributeExpr`
(user types walk as attributes). API auto-naming happens in `WalkSets`, not
`Validate`. JSON-RPC endpoints need method-level `JSONRPC(func(){})`; shared-route
diagnostics arrive via `eval.MultiError` (asserted message context, not type).
Shared static error names rejected unless a required `ErrorName` field exists.

### httpsvc — `expr/http_service.go` (12 details)
Parent `FullPaths()` may be `"//"`; child assertions use the canonical endpoint's
first route path. "Parent that is also a child" = direct self-parent/cycle (chains
are legal). Root HTTP errors are revalidated per service (2 services → 2
diagnostics). `Response` requires a valid response argument.

### methodval — `expr/method.go` validation (13 details)
`no` lines asserted via error presence + marker names (`username`, kind names in
security diagnostics). Inline error declarations must match the service contract.

### svcerrors — `expr/service.go` error surface (8 details)
`ServiceExpr.Method`/`Error` are excised here, so the suite iterates
`svc.Methods`/`m.Errors` directly. All `no` lines: error presence + name markers.

### attachsvc — `expr/root.go` attached services (9 details)
Hand-built method exprs need `Service` set (membership check runs first). `no`
lines: error presence + attribute-name markers.

### grpcend — `expr/grpc_endpoint.go` (14 details)
Service-level `Response` mappings only resolve service-declared errors; API-level
mappings need reusable API errors. `Meta` is method-level (not inside `GRPC`).
Explicit `Message` mappings trigger `rpc:tag` validation (unmapped errors
auto-tag). The cheat patch fails `go vet` (`stringintconv`) *and* fails 7 tests
behaviorally with vet disabled — verified separately.

### httperrexpr — `expr/http_error.go` (10 details)
D8: observed semantics — for object error types the explicitly `Header`-mapped
attribute lands in headers and the unmapped attributes land in the default
computed body; asserted exactly that (mapped→header, unmapped→body, error expr
resolved). D9: the RT-identifier content type is observable only when the result
type itself has no `ContentType` (the shared response-body finalize preempts with
the RT's own content type otherwise); asserted the identifier case only — the
precedence case was dropped as un-derivable from the commitment.

### httpresp — `expr/http_response.go` (13 details)
Status-0 error via `Response(0)`. `SkipResponseBodyEncodeDecode` is endpoint-level.
D5 (JSON-RPC header/cookie ban): JSON-RPC methods can't take `HTTP()` blocks, so
the test builds a normal endpoint, flips `e.Meta["jsonrpc"]`, and calls
`resp.Validate(e)` — exercises the committed check directly. D13 confirmed exactly:
`Body("message")` on `ErrorResult` → remaining fields map to
`apikit-attribute-<name>` headers with requiredness propagated; `Body(Empty)` →
all fields mapped; explicit `name:bbhdrname` mappings win.

**Refused/discrepancy — D12**: DETAILS commits `Dup` copying `Tag`, but the
reference `Dup` drops `Tag` (`[bbf bbv]` → `[ ]`) even via the DSL path. Asserting
either direction would fail gold or a spec-faithful solver; Tag is asserted
neither way and flagged here as a DETAILS-vs-reference mismatch.
**Refused — D13 tail**: the "non-object error result maps under a single
`apikit-attribute` key" case has no DSL-reachable trigger found (primitive/array
error types don't produce it; skip-flag is invalid on error responses); only the
object `ErrorResult` path is asserted.

### resultview — `expr/result_type.go` (15 details)
`CanonicalIdentifier` re-encodes params via `mime.FormatMediaType` (`; ` spacing).
Explicit `View("tiny")` meta on the RT itself triggers in-place projection (fields
outside the view dropped; only a default view remains); bad view meta panics.
`Project`: TypeName gains `Title(view)` (none for `default`), description gains
`(tiny view)`, Required filtered to view fields, identifier gains `view=tiny`
param preserving others; identifier already carrying `view=tiny` returns the same
pointer; same (type, view) projections share one object; recursive types terminate
(field-level `View("tiny")` resolves to the in-flight projection — `Same` pointer).
Collections project to `<Elem>Collection` arrays with projected elements.

**Refused — D11 non-RT element**: `CollectionOf` only accepts result types via DSL,
and a hand-built non-RT element panics inside `projectCollection`; asserted the
positive path only. **Refused — D12 first clause**: the "reuse the source's
generated-example identity" branch isn't observable without internal state;
asserted the documented fallback (projected identifier becomes `UID`).

## Cross-cutting observations for the pipeline

- `Validate()` returning a non-nil zero-error `*eval.ValidationErrors` is a
  recurring trap; suites must check `len(Errors)`.
- Several commitments describe behavior reachable only through DSL paths that are
  closed off (JSON-RPC method `HTTP()` blocks, non-RT `CollectionOf` elements) —
  direct `expr` construction plus the exported `Validate`/`Finalize`/`Project`
  calls is the reliable black-box fallback.
- One genuine DETAILS-vs-reference mismatch found (httpresp D12 `Tag`); flagged
  rather than asserted.
