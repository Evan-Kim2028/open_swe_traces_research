## Per-unit notes

### apiversion
5 assertions: headerless request proceeds; interior version accepted,
exterior rejected; sentinel `ErrUnsupportedAPIVersion` via `errors.Is`;
guard fires pre-network on a hand-built request.
`no` (D3): asserted shape — a version that is not a real calendar date but
orders inside the window is accepted ("ordering, not date parsing"), without
pinning the lexicographic mechanism.

### auditstream
5 assertions over the eight vendor constructors: `Enabled` mirrors the arg;
`VendorSpecific` holds the passed config by identity; `StreamType` non-empty
and pairwise-distinct across vendor families; the S3 pair shares one tag
while differing in payload type; nil cfg never panics and stores a typed nil.
`no` (D3, D4): asserted distinctness/equality shape, never the literal
vendor strings.

### boolresp
4 assertions through `Activity.IsStarred`: 200→(true,nil); 404→(false,nil);
500 and transport failure propagate; 404 detection keys on status regardless
of body (unparseable, empty, empty-object).
`no` (D4): the wrapped-`ErrorResponse` edge is unreachable through the
exported surface (the service method builds the error itself), so the suite
asserts the status-keyed shape and leaves unwrapping unasserted.

### brnotprot
4 assertions through `Repositories.GetBranchProtection`: the documented
"not protected" message translates while a different message on the same
status does not; transport failures never translate; a match returns
`ErrBranchNotProtected`; other errors propagate with their own message.
`partially` (D1, D2): asserted the message-vs-status distinction and
non-API-error propagation, not the match's exact field mechanics.

### comfortfade

`no` (D3, D4): asserted as shape — an error surfaces with zero server hits /

### credhdrs

### enturls

### errfmt

## Refused / weakened DETAILS lines

- **signmsg D1** ("a nil signer is rejected with an error"): unreachable
  black-box. A nil-interface signer skips signing via the surviving option
  dispatch (`opts.Signer != nil`), so the guard never runs; a typed-nil
  signer reaches it as a non-nil interface and — under gold — panics calling
  `Sign` on the nil func value (verified in-image). The commitment's literal
  form cannot be asserted without failing gold, so the suite asserts the
  reachable complement: no signer → the request proceeds unsigned (no
  signature materializes). Documented in the contract row.
- **boolresp D4** (wrapped `*ErrorResponse` counts): the unwrapping edge is
  unreachable through the exported surface — `parseBoolResponse` sees only
  errors the client itself constructed. Asserted instead: 404 detection
  keys on status regardless of body content.
