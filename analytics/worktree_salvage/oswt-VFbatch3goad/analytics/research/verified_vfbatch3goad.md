# Hidden test verification — authored_batch3/goa (VFbatch3goad)

2026-09-21 — authored and Docker-verified black-box hidden suites for the
goa `expr` units of `authored_batch3`, plus `_author/contract.md` for every
verified unit so the cohort can be staged (`stage_units.py` reads
contract.md unconditionally).

`gold.patch` was never opened. Every assertion is graded against
`_author/DETAILS.md` commitments, `api.md`, and exported black-box
behaviour only; upstream goa sources were consulted to understand fixture
plumbing (root binding, lifecycle order), never to import assertions that
the spec wall does not commit to.

## Method

- Suites live at `tests/hidden/expr/<unit>_bb_test.go`, all `package
  expr_test`, exported API only, one `TestDetailNN` per DETAILS line —
  the numbering traces a failure back to a commitment.
- Fixtures are hand-built `expr` trees; where lifecycle code needs a bound
  design the fixture registers services on a fresh `RootExpr` and calls
  `root.WalkSets` (the same binding the DSL produces), then drives
  `Prepare`/`Validate`/`Finalize` at the level production code uses.
- `tests/test.sh` per unit is generated by
  `experiments/pipeline/authored_batch3/_tools/gen_test_sh.sh`:
  sha256-guarded hidden-file install into `/app`,
  `go test -run '^(TestDetailNN|...)$'`, reward at
  `/logs/verifier/reward.txt`.
- Docker gates via `_tools/verify_goa.sh` in `ladder-base:goa`
  (3ce473c574db, go1.25.14): excised+hidden must FAIL, +gold must PASS,
  +cheat must FAIL, and neither gold nor cheat may touch a `*_test.go` or
  `tests/` path (A12, checked by patch-path scan — every patch touches
  exactly one non-test source file).

## `Inferable: no` assertion policy

`no` rows assert shape, never the literal: an error exists and names the
offending field/type/kind/scope; or a relational outcome holds (pointer
identity, set membership, ordering of identifiable markers, dedup counts,
precedence winners). Exact message prose is never pinned. Examples:

- `grpcend` D3 (stream-compat precedence): asserted via enable/disable
  under each meta level plus shadowing — the key string itself is the
  documented constant, precedence is what is checked.
- `grpcend` D14 (inherited-error diff): asserted that validation reports
  an error naming the mapping and its declaring scope; wording unpinned.
- `httpresp` D13 (`apikit-attribute-*` mapping): asserted the mapped
  element name contains the `apikit-attribute` prefix case-insensitively,
  skipped names stay skipped, and requiredness propagates — header casing
  unpinned.
- `svcexpr` D9/D10 (localhost URIs): asserted the appended host/URI
  scheme and that later services reuse it — the exact port literals are
  arbitrary and not asserted.
- `rootval` D12 (relocated-type diagnostic): asserted the dependency
  path notation (`a.b`, `[]`, `[key]`/`[value]`) appears — the fix-hint
  prose unpinned.
- `defval` D2 (per-context diagnostics): asserted each nesting context
  surfaces an error naming the offending position; label literals
  unpinned.
- `secschemes` D6 (URL validation): asserted all three malformed URLs
  are reported (coverage), order-free — an early draft pinned ordering
  and was corrected.

## Refused / weakened assertions

- `httpresp` D12 `Tag`: DETAILS lists `Tag` among the scalar fields
  `Dup` copies; the observed implementation does not copy it. Tag is
  asserted neither way — the contract row lists the fields that are
  copied and the DETAILS mismatch is flagged here rather than bent.
- `methodval` D9: the merged interceptor set is not observable as state
  after `Prepare`/`Finalize`; it is asserted through `Validate`
  diagnostics (the merged set is what interceptor validation checks),
  which is the behaviour DETAILS commits to.
- `resultview` D11 negative case (non-result-type collection element):
  rejected by panic rather than by returned error, so the assertion is
  "rejected (error or panic)" — the contract states the rejection
  requirement, not a mechanism.
- `httperrexpr` D9: the result-type-identifier content-type path is only
  reachable when the body keeps result-type identity (non-object result
  type); the fixture uses that path and asserts the identifier wins
  while an explicit response content type is preserved.

## Fixture notes (reusable)

- `Validate()` returns a non-nil zero-length `*ValidationErrors` on
  success — assert on `len(err.Errors)`/message text, never `err !=
  nil`.
- `AttributeExpr.IsRequired` delegates to the *user type's* attribute
  when `Type` is a `UserType` — requiredness fixtures must set
  `Validation` on the user type's own attribute, not the wrapper.
- `GRPCErrorExpr`/`HTTPErrorExpr` mappings must carry a prepared
  `Response` (non-nil `Message`/`Headers`/`Trailers`/`Cookies`) before
  `Prepare` may duplicate them.
- `HTTPResponseExpr.Finalize` does not compute the body — bodies are
  assigned by endpoint-level `Finalize`; error-attribute remapping only
  runs for `ErrorResult` bodies that are nil/empty or carry
  `origin:attribute` meta.
