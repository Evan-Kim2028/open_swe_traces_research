# Hidden test verification — authored_batch3/goa (VFbatch3goab)

2026-09-21 — verification + contract sweep, second pass over the same cohort.
`VFbatch3goa` (2026-09-20) wrote and Docker-proved the 12 hidden suites but
produced **no `_author/contract.md`**, leaving the cohort unstageable at any
rung (`stage_units.py` reads contract.md unconditionally). This run closes
that gap and re-verifies every unit end to end in this worktree.

`gold.patch` was never opened in this worktree. Behavioural claims were
graded against `_author/DETAILS.md` commitments only; the adopted contracts
are the reconciler-stage output (derived from hidden assertion + gold hunk
per `reconciled_contracts.md`), which carries the A13 gold-consistency
guarantee a blind write cannot.

- **Harness**: `experiments/pipeline/authored_batch3/_tools/verify_goa.sh`

  excised+hidden → FAIL, +gold → PASS, +cheat → FAIL, and reports whether

  `go test -run '^TestDetail'`, `/logs/verifier/reward.txt` — so every shipped

## Audit of the adopted suites (done here, not inherited)

- Per-line `Inferable:` labels in DETAILS.md match the label written in each
  test header, in order, for all 144 commitments across 12 units.
- Literal scan inside `Inferable: no` test bodies: all asserted literals are
  either `bb*` fixture identifiers (asserted as markers inside errors —
  shape), DSL-surface constants (credential kind names, OAuth2 grant names,
  `grpcs`, the `view` media-type param), or derivable transforms of the
  input (`BbT9` + `Title(tiny)` = `BbT9Tiny`). No test pins unguessable
  error prose; `no` assertions use `Contains`/`Same`/`HasSuffix`/set
  membership, never `Equal` on a gold sentence.
- No `Test*` outside `TestDetailNN`; no `t.Parallel`, no sleeps — the
  `test.sh` selector covers the whole suite.

## `Inferable: no` assertion policy (as verified)

`no` rows assert shape only: an error is produced and the diagnostic names
the offending field/type/kind via `bb*` markers; or a relational/structural
outcome holds (pointer identity, set membership, prefix ordering,
injectivity, dedup counts). Exact error prose is never asserted. Worked
examples checked by hand: secschemes D1 (two spellings disagree on exactly
one kind — injectivity + a count, never the spellings), svcexpr D1 (scheme
of malformed input ∈ documented codomain), methodval D6 (error names the
credential kind), defval D10 (error names the field/key/key-type),
resultview D9 (description `Contains` "tiny view" — the name+`view` shape,
not the ` (tiny view)` literal).

## Refused / weakened assertions

- `httpresp` D12: DETAILS commits `Dup` copying the tag field, but the
  reference `Dup` drops it (DETAILS-vs-reference mismatch found by
  VFbatch3goa). Tag is asserted neither way; the contract row lists the
  scalar fields it does copy and omits tag. Flagged, not bent.
- `httpresp` D13 tail: the "non-object error result maps under a single
  `apikit-attribute` key" case has no DSL-reachable trigger; only the object
  error-result path is asserted, and the contract's coverage row is scoped
  to it.
- `httperrexpr` D9 precedence branch: the result-type-identifier content
  type is observable only when the result type carries no own content type;
  only the derivable case asserted.
- `resultview` D11 negative (non-result-type collection element): not
  reachable via DSL; positive shape only. D12 first clause (reuse of a
  generated-example identity) is not black-box observable; the contract and
  test cover only the fallback (UID = projected identifier).
- `apiexpr`: **incomplete unit** — ships `cheat.patch`, `gold.patch`,
  `excised/` only; no `DETAILS.md`, `api.md` or `bugreport.md`. Nothing to
  grade against, no suite written. Needs a re-author pass before it can
  enter the bank.

## Notes for staging

  installed `/app/expr/...` copy), writes `/logs/verifier/reward.txt`.

- Recurring trap documented by VFbatch3goa and relied on here:
