# New Go repos for the bank — 2026-09-19

Two new repos prepared through the existing recipe (clone at pinned commit → strip `.git`
→ `identity_pass` module+brand rewrite → `ladder-base:<name>` image → offline
`go test ./... -count=1` under `--network none`), to test that the pipeline transfers to
arbitrary Go repos and to widen the bank beyond helm/kops/gin-style surfaces.
Log: `outputs/NEWREPOS.log`. Driver: `scripts/prepare_newrepos.py` →
`openswe_traces/synth/newrepos.py` (same path as `repos2.py`, but the Dockerfile `FROM`
follows the repo's own `go` directive — the `base_dockerfile_for` fix for
fresh-laptop defect 2).

### Selection rationale

`go-git` and `bbolt` keep on numbers AND on the difficulty lever that matters
(`authoring_hard_l0_units.md` §3.1: edge-case surface — empty input, duplicates,
reserved values, boundaries, ordering, error-vs-zero). They also add two domains the
bank lacks: VCS plumbing/parsing and embedded storage/transactions. `fasthttp` passed
the threshold (9 pkgs) but is wire-HTTP — adjacent to gin's closure style. `viper`
passed with zero margin (5 pkgs, one nested module `remote/` excluded from `./...`)
and config-precedence overlaps the helm/kops closure style. Both trees stay on disk
under `experiments/pipeline/repos2/` for future use.

| bbolt | root `boltstore`, `tests/failpoint` | root hit the 20m `-timeout` cap (Elapsed=1200.2s, "test timed out after 20m0s") — `concurrent_test`/`simulation_test`/`manydbs_test`/`quick_test` are heavy; zero individual test failures in root. `tests/failpoint` needs gofail injection builds. | fasthttp | root `httpkit`, `fasthttpproxy` | FS-compression tests (timing/FD-sensitive) + proxy-env tests. |
| viper | none | clean 5/0 — but no margin under the ≥5 rule. |
| buntdb | none | 1 passing package is the whole repo. |

Skipped packages are mostly no-test packages (examples, internal helpers).

```yaml
  - name: bbolt
    url: https://github.com/etcd-io/bbolt.git

    language: go
    src: experiments/pipeline/repos2/bbolt/src

    rebrand:
      "go.etcd.io/bbolt": "example.internal/boltstore"
      "github.com/boltdb/bolt": "example.internal/boltstore"
```

The maps point **upstream module path → tree identity**: the failure mode they prevent
is an author/verifier recognizing the repo and emitting upstream imports
(`go.etcd.io/bbolt`, the `/v5` or src-d-era go-git paths, the `boltdb/bolt` ancestor).
Package *names* are not renamed by `identity_pass`, so bare tokens like `bbolt` are
deliberately absent — mapping them would corrupt `bbolt.Open(...)` selectors in
authored tests.

Identity pass results (`identity.json`): go-git `github.com/go-git/go-git/v6` →
`example.internal/gitkit/v6` (540 files, 18,617 protected literals — test strings are
skipped); bbolt `go.etcd.io/bbolt` → `example.internal/boltstore` (85 files, 1,885
protected). External deps (`go-git-fixtures/v6`, `go-billy`, `gcfg`, `gofail`) correctly
untouched — they must resolve to real modules.
