## How the survey was used

The NEWREPOS survey listed 15 bbolt closures with the behavioural
commitments each offers. The 25 units map onto all 15; closures holding
several independent commitment clusters were split so every unit keeps a
**disjoint non-test file set** (one file per unit, 25 units → 25 files):

- bucket.go closures #1, #2, #6, #7, #9 → `bucket` (Put/Get/Delete +
  Create*/DeleteBucket/MoveBucket + sequences + ForEach + Stats/Inspect;
  one file, one cohesive surface)
- cursor.go #3 → `cursor`
- tx.go #4 + #14 (snapshot copy) → `tx` (Commit/Rollback/OnCommit/ForEach
  + WriteTo/CopyFile/Page)
- db.go #5 → `db` (Open/init/page-size recovery/Begin/Close lifecycle)
- node.go #8 → `node`
- tx_check.go #13 → `txcheck`
- compact.go (compact library function, survey #15's compact command) →
  `compact`
- internal/common #11 → `meta`, `page`, `inode`, `inbucket`, `loadutil`,
  `verifyenv` (six disjoint files)
- internal/freelist #10 → `flarray`, `flhashmap`, `flshared`
- internal/surgeon #12 → `surgeon`, `xray`; the guts_cli page readers the
  survey folds into #12 → `gutscli`
- cmd/bbolt/command #15 → `cmdutils`, `cmdget`, `cmdpage`, `cmddump`,
  `cmdpages`, `cmdsurgerymeta`

Authoring was FOR difficulty per `authoring_hard_l0_units.md`: every
unit's contract commits to edge behaviour *not* inferable from
signatures alone — sentinel values (`PgidNoFreelist`, free id ≤ 1 panic),
exact error triage order (magic → version → checksum), layout offsets
(element-relative `pos`, meta after the 16-byte header, 1024-byte meta
reads), stride/order rules (1 vs 1+overflow, txid%2 meta pick, run-start
reset), and error-vs-zero conventions (`Allocate` → 0, `Get` → nil,
`Bucket()` → nil on k/v names). The in-tree tests pinning each
commitment were removed by the excision patch (the discoverability
knob); `DETAILS.md` records which removed test covered each numbered
commitment and whether it is inferable from the remaining tree.

## Generation and verification

Units are generated by
`experiments/pipeline/authored_batch2/bbolt/_gen/generate.py` from three
spec files (`spec_root.py` 7 units, `spec_internal.py` 12, `spec_cmd.py`
6). Per unit it builds an excised tree (stubbed bodies keep
declarations; covering `*_test.go` deleted or selected test funcs
stripped), a cheat tree (worked-example-only bodies), emits
`excision.patch` / `gold.patch` / `cheat.patch`, writes
api/contract(L2 prose + coverage table)/bugreport(L0)/difficulty/
DETAILS/closure, then verifies:

- `go build ./...` + `go vet ./...` on **both** excised and cheat trees
  (the one upstream vet complaint — `db_test.go` copylocks — exists on
  the pristine tree and is filtered, everything else must be clean);
- `gold.patch` applied to the excised tree restores every stubbed file
  byte-identically to pristine (gold never touches `*_test.go`, A12);
- `cheat.patch` applies cleanly.

Result: **25/25 clean** — every excised tree compiles, every cheat tree
compiles, every gold restores pristine. Log: `outputs/AUnew2.log`.

`check_unit_overlap.py --extra /home/evan/Documents/oswt-AUnew2` (from
the main checkout): **25 new vs 0 existing — CLEAN, 0 overlaps.**
Non-test file sets are disjoint by construction (one file per unit);
several units share deleted *test* files across their own trees
(`db_test.go`, `tx_test.go`, the command/surgery test files) — the
checker ignores `*_test.go` by design, and each unit is an independent
tree.

Machinery fixes made during this session (the earlier scaffold failed
on first run): `find_func` now skips `struct{…}`/`interface{…}` braces
in result types (broke `flhashmap`'s `map[…]struct{}` signatures);
`fix_imports` matches qualifiers only in real code (not comments/
strings), preserves aliases via `//alias:` markers so cheat trees can
restore `berrors`, and un-blanks single-line imports (`unsafe` in
inode.go); `go_check` filters the pre-existing `db_test.go` vet
complaint; spec fixes: `loadutil` delete paths, `bucket` cheat
pointer/vet issues + missing `sort`/`strings` imports, `tx.WriteTo`
named-return `err :=` redeclare, `txcheck` missing return.

## Notes for the verifier

- `db` deletes all 17 root `*_test.go` + `internal/tests/tx_check_test.go`
  — its surface (Open/Begin/Close) is exercised by every test, so the
  discoverability knob is maximal there.
- Shared *test*-file deletions across units (bucket/tx/txcheck on
  tx_test.go+tx_check_test.go; meta/loadutil/surgeon/gutscli/
  cmdsurgerymeta on the surgery command tests; the three freelist units
  on freelist_test.go) are deliberate — each unit is an independent
  tree, and check_unit_overlap ignores `*_test.go` by design.
- `tx` and `meta` additionally *strip* selected test funcs from
  `db_test.go` rather than deleting it, keeping the rest of the file as
  collateral.
- Cheats are deliberately wrong (map-backed fake store for bucket,
  constant returns, trivial bodies) — each compiles and may satisfy a
  worked example but fails any commitment outside the worked set.
- `verifyenv` has no dedicated test file; its only direct coverage was
  `common.Assert` call sites in `utils_test.go` (deleted).
- `bucket` keeps all node/spill/inline machinery live — the solver
  reconstructs Bucket semantics over real page code, which is what makes
  its Stats/Inspect/ForEach commitments non-trivial.
- bbolt's root test suite is heavyweight upstream (20-min timeout in
  NEWREPOS); the deleted-file lists keep each unit's remaining suite
  proportionate, but the verifier should still prefer targeted `-run`
  filters over `go test .` for the big root-package units (bucket, db,
  tx, node).
