# Overnight pipeline — discovery × L0–L6 flip points

## Question

On fresh Go repos, what is the flip point for Composer 2.5 vs Devin swe-2-max
when units are authored and verified by **separated** roles (author never writes
tests; verifier never reads gold), every Harbor pass is B9-audited, and the
solver climbs the **adaptive** ladder (C6 amended)?

The primary measurement is the **calibration curve**: pass rate vs ladder level
per (repo, solver). Flip points and author calibration are secondary.

## Config

| knob | value |
|---|---|
| Repos | `repos.yaml` (regenerated by `scripts/ops/rebuild_bases.sh`) |
| Author batch | 10 units / 30 min brief; session timeout from `timeouts.py` |
| Existing batches | consume `authored/<repo>/` and `tasks/<repo>/` (external Devin); do not re-author `_author/` units; do not re-verify `*-L2/validation.json` with B4=pass |
| Verifier | black-box properties; B4 required; gold applied blind |
| Package | L2 first; L0/L1/L3–L6 via `affordance.py` only on demand |
| Solve | adaptive: climb `climb_levels: [2, 5, 6]` one attempt each; confirm 2 extra at the candidate and the level below; L0 probe when L2 passes; L1/L3/L4 on demand |
| Solvers | `solver_order: [cursor, devin]` (Composer 2.5, then Devin swe-2-max) |
| Composer cap | 1_000_000_000 in+out tokens; then solver switches to Devin (unchanged) |
| Devin cap | `devin_slots` (default **6**) at `/tmp/devin.slots`, shared file semaphore with Harbor |
| Timeouts | Devin 14400s trials / 90 min sessions; Composer 3600s / 60 min; Grok 3600s / 60 min. Timeouts are class (d), not fails |
| Control | `predicted_flip: L<k>` and optional `control: true` in `difficulty.md`; control unit runs first; a failing control pauses the repo |
| Docker | laptop 4 concurrent trials, VPS 2; skip launch if load > 2× cores |
| Egress | `[agent]` allowlist (Cursor hosts), `[verifier]` no-network |
| Audit | B9 on every pass; hard fail → class `hacked`, excluded from flip. Web-use → rerun once, then exclude |

Do not touch `experiments/harbor_nex/jobs` or existing Harbor task dirs.
Do not launch Harbor from unit tests or `status`.

## Resume

State is `experiments/pipeline/state.db`. Every stage (`prepare`, `author`,
`verifier`, `package`, `solve`, `aggregate`) is idempotent. Re-running `run`
or `dry-run` continues unfinished steps; `DONE` / `REJECTED` / `SKIPPED` are
not repeated. A crash mid-step leaves status `running` or `failed` and is
retried. A failing control unit pauses the rest of that repo (`paused`).
Logs: `experiments/pipeline/logs/pipeline.log`.

Author/verifier consume batches that already exist:

- `experiments/pipeline/authored/<repo>/<unit>/_author/`
- `experiments/pipeline/tasks/<repo>/<unit>-L2/validation.json` (skip verifier if B4=pass)

## What was measured

Per task: repo, unit, family, closure size, lines, per-level pass counts,
adaptive flip point (confirmed or not), predicted flip, control flag, solver,
audit class, hacked count, tokens in/out, wall minutes.

Dashboard: calibration curve per (repo, solver, level), nearest-50% level,
inter-attempt 2-1 split fraction, author calibration (MAE / exact / off-by-one),
hacked (B9) counts, early-warning flags **with their action text**, flip-point
histogram per solver, Composer tokens used.

## Devin concurrency finding (2026-09-19 03:40Z)

At 7 concurrent swe-2-max sessions (3 CLI verifier + 1 CLI author via the pipeline + 3 Harbor trials) all three verifier sessions hit "Reached free model rate limit ... resets in ~20 s" within minutes and died. Treat any hit as a rolling-window limit: back off 20 min, then resume at lower concurrency. Operating target: 5 sessions total (3 CLI + 2 Harbor). `devin_slots` in config.yaml set to 5.
