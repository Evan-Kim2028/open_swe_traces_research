Tools on this box: `codegraph` CLI (`codegraph init && codegraph index` in a repo; `codegraph query <symbol>`, `codegraph callers|callees|impact <symbol>`, `codegraph affected <files>`; run `codegraph --help` first), Go 1.23 at /usr/local/go/bin/go, DuckDB via `uv run python`.

1. 3. `codegraph init && codegraph index` in each repo; record index time and symbol counts.
4. Candidate selection: list exported functions/methods whose `codegraph callers` span >= 2 packages AND that are covered by at least one passing test (use `go test -coverprofile` per package to find covered functions, or `codegraph affected`). 5. Bug injection: for each candidate, write a minimal semantic bug (not a syntax error): off-by-one, inverted condition, swallowed error, wrong nil check, wrong map key, dropped goroutine sync. 7. Verifier breadth check on 3 bugs: write one alternative correct fix and one cheat fix (e.g. special-case the test input); confirm the f2p tests accept the alternative and reject the cheat.
8. Difficulty prior: for each valid bug, record hops = shortest path in the graph from a failing test file to the injected symbol, and number of distinct files in the impact set.
